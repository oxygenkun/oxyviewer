# 人物模块：页面、审阅流程与识别方案

状态：**阶段一人工工作流、手动跨场次历史关联及基础 Person tag 同步已接入；人物域的分析账本、检测/特征缓存与阈值检索已在 `oxy-people` 内实现并测试，但尚未接到应用**。更新于 2026-09-25。
本文是人物模块的单一入口；页面规则、状态语义和当前算法决策以此为准。文末研究报告保存实验协议、原始分母及复现方法，不充当交互规范。

当前主应用支持人物 Tab、文件夹范围的人物与待审数、Loupe 图上人脸／人体框添加与修正、逐实例审阅、人物／状态过滤，以及场次身份和单张参考管理覆盖页。Grid／Loupe 共用后端整目录过滤、去重、排序和分页；与文件名、类型、评级、旗标及 tag 条件取交集。初次手工建人物显示全部照片以便添加实例；选择已有主体默认待确认，也可清除人物过滤。没有模型时可完成整个人工流程。

人工记录、审阅及修框历史、场次称呼和单张参考保存在 SQLite，写入使用 requestId 和 revision；源图变化时禁止直接审阅旧框并提供待复核过滤。修框保留旧值与决定历史，将原有非否定决定改为待确认；明确的“不属于”不自动复活。撤销参考实例归属或修框会清除该参考，不自动撤销独立的场次身份。管理页支持改名、替换单张参考及撤销身份确认，关闭回到原视图。参考清晰度由用户核对。

已确认的场次人物可在管理页建立稳定历史人物，或核对当前和历史参考缩略图后关联已有历史人物；关联可撤销，撤销场次身份也撤销关联。历史人物保留首次建立时的参考路径与源版本；源图变化或不可用时不允许从该参考建立关联。当前历史列表仅供人工选择，尚无相似度建议及跨场次参考图库。

`asset_tag_sources` 已为现有 tag 添加保守的 `legacy` 来源迁移，并分别记录新的手工编辑、sidecar 导入与 Person 贡献；`asset_tags` 仍是筛选和 XMP 使用的有效并集。sidecar 移除不删除手工或 Person 来源，且有效集合与导入值不同时重新排队写 XMP。管理页可为稳定历史人物明确选择已有 tag、启用／关闭同步；同一照片由至少一个有效“属于”实例贡献一次，可针对历史人物在单张照片上停止或恢复同步。标签移除确认框会显示来源，并在存在 Person 来源时引导到人物管理。删除 tag 后映射保留断链状态，不按名称重建。同目录改名在同一事务中迁移人物实例、历史参考及 tag；跨目录移动暂将旧实例标为待复核且不携带 Person tag，需人工重新核对。尚未提供绑定新建 tag、联动改名、身份拆并、完整跨目录人物迁移及真实桌面应用验证；浏览器 demo 已验证绑定、关闭及单图覆盖。

**仍未实现的是应用侧接线，不是领域层**：模型安装命令、分析作业 IPC、候选查询命令、前端入口、
文件夹级聚类与检索的任务登记，以及 macOS Core ML 的实机验证。人物域的存储与规则——分析运行账本、
幂等请求、分批任务领取、检测与特征缓存、阈值检索、实例对齐——已在 `oxy-people` 内实现并有测试，
但没有一条命令把它们接到界面上，所以「自动分析可用」仍是假命题。阶段一的待查入口是“未加入此人物”和“源图变化／待复核”，不伪装为模型的缺脸／歧义结果。源版本当前使用文件大小与毫秒修改时间；完整 SourceRevision、重算对齐、作业取消及路径迁移属于后续阶段。验证范围和限制见 [阶段一验证记录](research/2026-09-23-person-manual-workflow.md)。

## 目标与边界

用户在一个当前文件夹（下称“场次”）内，先发现可能是同一人的照片，再选定某个人物直接在现有 Grid／Loupe 浏览和审阅；可逐步确认此人的参考照片与身份。**场次只是文件夹范围的称呼，不是另建的实体或 ID**；同一文件夹中的照片属于同一场次，切换文件夹就切换范围。若已有历史已确认人物，再把当前文件夹中的人物与历史身份建立经人工确认的关联。**候选同人、匿名簇、已确认身份是三个不同概念**，相似度和聚类都不能自行宣布身份已确认。

现场筛图优先召回，允许候选列表包含较多异人照片，由人排除。目标照片限定为**人体清晰、正面或侧面、无遮挡且人脸清晰、正面或侧面**；模糊／遮挡／背对的人体，以及模糊人脸，不属于这项现场需求。自动检测漏掉但人工判定合格的照片仍是系统漏检，不能从召回分母删去。可由用户手工补选或进入待查队列。

## 对象与状态

| 对象 | 含义 | 关键状态或关系 |
| --- | --- | --- |
| 场次 | 当前选择的收藏夹文件夹及其本次人物分析范围 | 未分析、分析中、可审阅、需重算／失败；切换文件夹时不混用结果 |
| 人物实例 | 一张照片中的一个具体人脸／人体；同图可有多人 | 检测框、脸与人体关联、质量与特征可用性、人工修正；无法确定关联时保持歧义 |
| 匿名簇 | 本场次中模型建议属于同一人的实例集合 | 临时编号、成员及待查候选；不等于姓名或历史身份 |
| 照片审阅决定 | 针对**选中簇与某张照片中的指定人物实例** | 待确认、确认属于、不属于、暂缓；保留操作者可回改的决定 |
| 场次身份 | 用户确认该簇代表谁，可以先用临时称呼 | 待确认、已确认；确认身份与逐张审阅分别记录 |
| 历史人物 | 跨场次复用的已确认身份及参考图库 | 只有明确确认后才关联；匹配结果先为建议 |
| 参考照片 | 用户核对过人物实例和质量的查询依据 | 默认 1 张清晰人脸；可增至 3 张已确认同人、尽量覆盖正／侧脸 |

“已确认”需要明确其层级：一张照片属于某簇的决定、该簇的场次身份、以及当前簇与历史人物的跨场次关系可以分别待确认。改名不自动确认簇内所有待审照片；确认一张照片也不自动确认历史身份。任何手工否定结果须从对应簇与候选中移出，并在重新计算后继续生效。

## 页面结构

```text
左侧边栏                         中央 Grid / Loupe             右侧 Loupe 信息栏
┌ 浏览 | 人物 ┐                  当前文件夹的照片                 ┌ 人物审阅 ▾ ┐
│ 人物列表与待查入口 │            人物筛选作用于两种视图         │ 选中实例、归属、操作 │
│                 │                                             ├ 图片详情信息 ┤
│ 收藏夹       ▾  │                                             │ 原有元数据等 │
└─────────────────┘                                             └─────────────┘
```

- 左栏顶端以 **浏览／人物** Tab 切换。浏览 Tab 保留现有浏览组织；人物 Tab 上部展示场次人物、待确认数和未分组／缺脸／多脸歧义入口。
- 人物 Tab **底部仍有收藏夹**，用于切换当前要解析的文件夹。它是独立可折叠的分区，交互类似 VS Code 左栏分区标题：点标题收起／展开，收起后仍露出“收藏夹”标题和当前文件夹提示，不清除选择；上方人物区获得空间。切换 Tab 后仍记住当前文件夹与折叠状态。选择新文件夹会切换场次范围及对应人物结果，不把旧场次结果显示成新场次人物。
- 中央仍是原 Grid／Loupe、胶片条、快捷键、排序、选中和图片导航。人物是**附加过滤条件**，不是独立阅图器：选簇后可选“待确认／已确认属于／全部候选”等状态，Grid 和 Loupe 看到同一结果集，导航只在当前过滤结果中移动；切换视图保留当前人物、状态过滤和当前位置。普通浏览筛选的组合规则和可清除条件应在界面可见。无结果时显示范围与清除入口。
- Loupe 右侧原有详情持续可见。人物审阅是**可折叠的上方信息栏**，展开时显示当前照片中选中的人物实例、对应簇／身份、证据与审阅操作；图片详情在其下自然排布。收起人物审阅仅隐藏这段信息，不隐藏图片详情、不过滤或改变选中人物。Grid 可用相同审阅入口打开 Loupe 或对选中照片批量审阅，审阅状态一致。
- 主工具栏只适量增加“确认身份”入口以及人脸框／人体定位框的显示开关；框是查看与选择具体人物实例的辅助，不替代审阅决定。多人物照片须显式选中哪张脸，关联不明时提示人工指定，避免把整张照片误归给一个人。
- 人物管理（参考图、身份资料、历史匹配、簇拆分／合并、复核记录）用类似设置页的**覆盖页面**承载，关闭后回到原 Grid／Loupe、原筛选和位置。主界面不铺开完整管理表单。

| 页面／视图 | 进入方式 | 主要任务 | 返回时保留 |
| --- | --- | --- | --- |
| 人物 Tab + Grid | 左栏切 Tab、选文件夹或人物 | 看簇和待查入口；按人物及审阅状态过滤照片；批量选择 | 当前文件夹、人物、过滤、选中照片 |
| 人物 Tab + Loupe | 打开 Grid 中照片或直接切 Loupe | 指定图中人物，逐张审阅；右侧审阅栏在详情之上独立折叠 | 同一过滤结果与当前位置 |
| 人物覆盖页 | “确认身份”或人物列表管理入口 | 选参考、场次身份、历史候选、新建人物、拆并簇与复核 | 关闭后回原视图；未提交修改应提示保存或放弃 |
| 浏览 Tab | 左栏切回浏览 | 按原有照片组织方式工作 | 返回人物 Tab 时恢复其人物、过滤和收藏夹折叠状态 |

原型参考：[Figma 人物模块页面](https://www.figma.com/design/36UZGLGLhbTSRiwIsKfqAB)：Grid（`2:3`）、Loupe 审阅及收藏夹展开（`4:2`）、身份管理（`5:2`）、两栏收起（`13:2`）、仅收藏夹收起（`17:52`）。原型是静态设计，交互规则以本文为准。

## 从首次使用到历史匹配

1. **选择场次。** 在人物 Tab 下方收藏夹选文件夹。没有分析结果时显示“分析当前文件夹”；后台提取人物实例与特征、生成匿名建议，过程中仍可正常浏览。分析完成显示匿名簇和未分组／歧义／缺脸待查，不给匿名簇自动填姓名。重新打开或切换文件夹恢复该文件夹的审阅进度。
2. **选中人物开始现场过滤。** 点匿名簇中的一张清晰照片，并在多人图中明确选一个实例；也可直接在 Grid／Loupe 从某张照片发起“查找此人”。用这一张作为默认参考，展示当前场次“可能是同一人”的候选。选择簇后默认进入“待确认”过滤；人物、过滤状态及清除按钮在界面可见。推荐簇可以帮助入口和排序，但单图检索不依赖簇已完整或已具名。
3. **审阅照片。** 在同一 Grid／Loupe 逐图判断“属于／不属于／暂缓”，右侧人物审阅栏显示当前实例和证据，下方仍显示图片详情。确认后留在相同过滤条件；若当前图仍有待审人物实例，不自动跳图。当前图相关实例都处理完且它不再属于“待确认”时，才导航到过滤结果中的下一张。多人图的决定只作用于选中实例。人工修框或选错脸后可以重新提取／检索，同时保留人工审阅决定，冲突交给待复核。
4. **确认场次身份与参考。** 在人物覆盖页核对簇成员，选 1 张质量最高且确实是此人的清晰人脸参考，填写姓名／临时身份，确认该场次身份。若有三张**已经人工确认属于同一人**的高质量参考，可选正／侧脸兼顾的 3 张模式；切换模式要用各自校准的规则重新排序候选，不直接沿用单图阈值。身份可以先待确认，照片审阅可以继续。
5. **有历史库时再匹配。** 以当前已核对实例／参考向历史已确认人物图库检索，展示候选身份及其参考、当前与历史的对照。用户选择“匹配此历史人物／新建人物／暂缓”；自动结果只做建议。确认后建立跨场次关系，历史图库只收纳用户明确确认且合格的参考；待确认簇和未经核对的候选不自动污染图库。历史库为空时这一步完全跳过，不阻断当前场次审阅。
6. **后续到片与修正。** 新照片先进入当前场次待确认队列，已确认身份不使新候选自动通过。错误合并可拆簇，漏组可人工并簇或关联实例；操作应保留来源、手工决定和可撤销的关系。切换人物、过滤条件、Tab 或关闭覆盖页都不丢失已提交的审阅状态。

待确认队列包含模型返回的未审候选，也应单列无可用脸、关联歧义或未归组的待查照片。后者不能被解释为“照片里没有这个人”；用户可进入原图、手工指定实例并继续查询。用户确认的“不属于”不因阈值调整再次作为普通待确认返回，除非明确进入复核流程。

## 当前识别与聚合决策

| 阶段 | 当前方案 | 自动化边界 |
| --- | --- | --- |
| 检测与实例入口 | 自动人脸／人体框、关联与质量证据；多人、缺框或关联不明可手工选脸／修正 | 质量决定是否适合现场目标，**不代表身份**；合格照片检测失败也须待查 |
| 现场 one-shot 候选 | **AdaFace 官方权重的人脸向量**作为非商业研究默认来源；默认 1 张人工核对且有可用人脸特征的清晰参考，候选按相似度排序。旧第三方 ONNX 的 `0.300` 只保留为先前实验对照 | 仅“可能同人”，逐张人工确认；官方权重已在冻结数据上探索性复算，但默认阈值须用未见场次重新校准 |
| 缺脸补召 | 候选缺可用脸特征时，以独立的 OSNet 体貌向量提供**弱证据候选**，并标明来源；查询本身缺脸特征则先请用户重选／补选清晰参考 | 不把固定 70% 人脸＋30% 体貌融合设默认；体貌候选不能自动并簇或确认身份 |
| 可选三参考 | 只用 3 张已确认同人且高质量的图；兼顾正／侧脸，采用单独校准的聚合与阈值 | 现有实验未证明比单参考提高召回；不得直接复用旧模型阈值或自动从候选扩展参考 |
| 首次零图库匿名聚合 | 以 **ArcFace 人脸证据的保守核心簇**作为下一版产品设计候选，无法安全归组者留单例／待查；用单图检索与人工审阅补召 | E0–E6 尚未形成可确认身份的生产聚合方案；纯脸核心本身也未通过最终验证，LVFace、质量加权、E3 原型吸附、E4/E5 邻域修正、E6 自动合并及固定融合均不能宣称已晋级为默认 |
| 跨场次历史匹配 | 对已确认历史人物图库做候选检索与人工确认；具名身份来自明确选择 | 当前没有跨场次、换装、真实图库拒识与误认的验收数据，阈值及自动接受规则**未定** |

聚合与选图任务的编码器不必相同：ArcFace 是匿名聚合实验的研究基线，AdaFace 是高召回单图过滤当前较优的实验选择。人脸与体貌向量分别保存、分别解释；“缺脸补召”只影响候选展示，不把弱体貌证据提升为已确认簇或历史身份。后台提取、缓存与增量更新必须遵守现有非阻塞打开文件夹、分页、取消及过期结果规则；具体后端设计如下。

## 后端实现设计（人工基础已实现，其余待实现）

以下是完整实现契约。人工阶段已实现 `oxy-domain/src/person.rs`、`oxy-people/src/identity.rs` 和薄 Tauri 人工命令，使用 `folder_people`、`person_manual_instances`、审阅／修框／身份事件、参考与请求去重表；手动历史关联增加了 `historical_people`、`folder_historical_links` 和关联事件。tag 来源账本与基础选择性同步已接入。`oxy-people/src/features.rs` 已接入固定版 sqlite-vec、可重建的特征空间与向量缓存、合法性校验及完整阈值查询；查询要求完整的当前文件夹源版本快照，先剔除过期向量再分页。`oxy-people` 已提供管线清单校验、指纹，以及离线文件／HTTPS 流的长度和 SHA-256 核验、取消与原子安装底层能力；下载函数尚未接入应用发布的可信清单和用户触发命令，亦无推理生产者或 UI 候选命令。作业、历史候选检索和应用服务编排仍待实现。人物数据与标签、收藏夹、索引共处同一个 `oxyviewer.sqlite`：文件、表声明和每一句语句属于 `oxy-store`，`oxy-people` 只持有同一个 `oxy_store::Store` 并写自己对行的规则。新增人物数据必须遵守 `cache`/`user` 的区分，并沿用 [资料库与状态](architecture/05-data-and-state.md) 和 [性能不变量](PERFORMANCE_INVARIANTS.md) 的边界。

当前管线清单的 `pipeline_fingerprint` 按阶段语义计算，`stage_fingerprint` 只纳入该阶段及其上游依赖；下载地址和许可记录变化不改变推理指纹。`stages_to_recompute` 比较旧／新清单，列出需要重算的阶段。特征空间用生产阶段指纹校验兼容性，每条向量另存完整管线指纹供追溯。更换人体编码器不会使独立的脸部特征失效，但依赖人体编码器的下游建议须重算。向量缓存格式版本为 3，实例缓存 ID 按文件夹和资产路径限定，旧版本只清除派生表。

`oxy-people/src/analysis_runs.rs` 现已持久化显式分析运行、文件夹 generation、幂等请求、取消、分批任务登记和前置阶段完成后才可领取的任务顺序。新运行会使旧运行失效；取消或被替代的运行不得继续领取任务。派生特征、检测实例和任务进度在同一事务中提交，核对当前 generation、任务键和一次性领取令牌；公开提交入口在写入前用 `oxy-fs` 重新观察真实文件，并与媒体缓存共用源版本算法。同阶段检测结果整体替换；源版本或生产阶段不匹配的旧缓存不会被查询。人工审阅表不受自动提交影响。新建／修正的人工实例另存完整源版本，旧人工实例的完整源版本为空，未重新核对前不能自动对齐。`oxy-people/src/alignment.rs` 只在同源、框有效、几何重叠足够且双方唯一时建议对齐；一对多、多对一、源变化及待复核都保留为冲突，不转移人工决定。失败阶段会阻断并记账同一文件的后继阶段。重启恢复会把未完成领取重新排队并废弃旧令牌，迟到 worker 不能提交。`oxy-people/src/analysis.rs` 从 `oxy-fs` 对所选文件夹做新的非递归扫描，按管线依赖排序每图阶段，以最多 256 条任务为一批登记；浏览缓存已有旧快照时仍能登记新增文件。扫描的枚举和属性读取阶段会检查取消，并且取消时不返回部分快照（`oxy-fs` 为此增加了 `FsError::Cancelled` 与 `scan_assets_with_progress_and_cancel`）。逐图登记不会封存整次作业：文件夹级聚类和检索尚未登记，不能把逐图任务完成误报为整个 pipeline 完成。上述模块尚未接到模型 worker／候选 UI。推理、自动调用恢复及进度 IPC 仍待实现；当前内部作业记录不代表自动分析可用。

### 模块职责与可替换接口

| 层 | 职责 | 边界 |
| --- | --- | --- |
| `oxy-domain` | `PersonId`、文件夹路径、实例定位、审阅决定、身份关系、模型状态、分页查询及错误码等公共序列化类型；`FeatureModality`、`PersonFeatureMatch` 也在其中，因为仓库要按它们读写 | camelCase；不暴露模型内部向量、文件字节或 Python 对象 |
| `oxy-people` | 人物的**全部**含义：身份、审阅、历史关联、参考、身份↔标签投影决策、实例对齐、分析编排、候选检索，以及检测实例、特征向量和分析运行的可重建缓存 | 不依赖 `rusqlite`（事务用 `oxy_store::{Connection, Transaction}`）；不依赖 `oxy-library` 或 `oxy-tags`，需要对方的行时调用 `oxy-store::repo` 的语句；不依赖 Tauri 或具体推理框架 |
| `oxy-tags` | 标签词汇、层级不变量、赋值来源账本、XMP 镜像，以及文件移动/复制/删除后标签状态的迁移入口 | 不依赖 `oxy-people`；人物身份推给照片的标签走来源账本，由人物侧写入 |
| `oxy-store` | `oxyviewer.sqlite` 文件本身：连接、WAL 只读连接、事务、全部表声明与迁移，以及**每一句语句**（`repo`，一个函数一句 SQL） | 不知道照片、标签或人物的规则；只按声明区分 `cache`/`user`/`marker` |
| `oxy-library` | 收藏夹，以及浏览、索引、资源投影各自的行为规则 | 不再持有任何人物或标签数据 |
| `oxy-fs` | 文件发现、路径规范化、源文件观察（`observe_file`）、可取消的目录扫描、受控文件操作及路径转移 | 人物模块不自行遍历目录或执行改名／移动／删除 |
| 模型运行适配器 | 检测、脸／人体关联、质量评估、特征编码、聚合／排序 | 消费媒体层提供的有界输入表示和短生命周期像素／张量；推理执行在有界后台 worker，不在 UI／async 线程 |
| `src-tauri` 与前端 | 薄命令适配、作业通知、`api.ts` IPC 包装与浏览器 demo；`src-tauri` 同时是**组合根** | Grid／Loupe 复用当前目录查询和分页；不传图像字节或全目录向量 |

领域 crate（`oxy-library`、`oxy-tags`、`oxy-people`）互为兄弟：各自持有同一个
`oxy_store::Store`，需要对方的数据时调用 `oxy-store::repo` 的语句，而不是调用对方。跨领域的
语句——包括「文件移动了」和「文件没了」这两个动作——集中在 `oxy-store/src/repo/cross.rs`。
应用层打开一次 `Store`，用 `Library::with_store`、`Tags::new`、`People::new` 各组装一个句柄。
`oxy-tags` 的测试有一条 `[dev-dependencies]` 边指向 `oxy-people`，用来驱动真实身份策略、证明
身份的主张会落成 `person` 标签来源；生产依赖没有这条边。

不要把“人物识别模型”做成单个不可拆的调用。定义版本化 `PipelineManifest`：`pipelineId`、`pipelineVersion`、各阶段 `stageId`／输入输出 schema、模型 artifact 的 SHA-256、运行时／预处理／后处理版本、特征空间 ID、距离度量及校准配置 ID。至少分离 `Detector`（脸／人体候选）、`Association`（脸体关联）、`QualityGate`、`Encoder`（face/body 独立）、`Clusterer`、`Retriever`。阶段输出用规范化的实例和证据契约传递，替换一个阶段只失效其下游派生物；不能把旧向量与新向量混在一个索引里。可以先以内置 Rust 适配器和有限的 manifest 注册表实现，不要求第一版支持任意第三方插件；适配器接口和存储格式应允许以后换模型、增加无脸检测流或调整关联策略。检测质量仅决定候选资格，不写成人物身份。

### 模型获取、安装与运行

- 安装包和主应用仓库不携带权重；首次使用时展示所需阶段、下载大小、来源、许可和本地磁盘占用，由用户触发下载。缺少模型时人物 Tab 显示可安装状态，普通浏览、tag 和已保存的人工人物资料仍可用。不要在打开目录时静默联网。
- 使用应用发布的**版本化可信清单**指定 HTTPS 下载地址、artifact 长度、SHA-256、许可/再分发说明、支持的目标平台和运行时要求；清单也允许日后发布替代模型。下载到 app data 的临时文件，支持取消与断点续传（仅在服务端校验器和已下载区间可靠时），完成后验长度与哈希，再原子安装到按 artifact digest 寻址的目录。拒绝不匹配文件、路径穿越、解压炸弹和不受信任的可执行载荷；离线导入遵守同一校验。下载失败保留可重试状态，不影响旧版本运行。
- 模型许可应按 artifact 单独记录和展示；许可不允许下载或本地使用的模型不得列为可安装选项。只从受信清单安装并启用运行适配器，不把远端清单当作任意代码执行指令。权重、缓存和运行时的清理各有引用检查：已安装的旧版本可在新版本完成验收后移除，正在运行或被选为当前 pipeline 的版本不能删除。

本项目当前人物模型方案按用户要求限定为**非商业研究使用**，默认权重来源选择 AdaFace 官方发布，而不是原有第三方 ONNX 转换件。[AdaFace 官方仓库](https://github.com/mk-minchul/AdaFace)提供 R100 WebFace4M PyTorch checkpoint，源码使用 MIT；[CVLFace 官方模型页](https://huggingface.co/minchul/cvlface_adaface_ir101_webface4m)提供另一套 safetensors 权重并要求遵守训练数据许可。两者格式、输入色序和特征空间不能混同。`oxy-people` 的安装校验现允许受信清单中标为 `ResearchOnly` 的产物，并继续拒绝 `Unresolved`；长度、SHA-256、HTTPS 来源和完整 pipeline 校验仍适用。当前研究已固定官方 checkpoint 和源码的长度与 SHA-256，并导出与 PyTorch 输出相符的 ONNX；应用内可信下载、转换及其安装状态仍待接入。单图检索的 0.300 阈值来自旧第三方 ONNX，切换官方权重后必须重新校准，不沿用旧向量或旧阈值。

SCRFD-10G 当前研究权重来自 InsightFace。其[官方模型说明](https://github.com/deepinsight/insightface/blob/master/python-package/docs/model_zoo.md#model-licenses)明确指出预训练模型仅供非商业研究，且自动下载与手工下载适用同一限制；在本项目当前限定的非商业研究用途中，可作为默认检测来源候选，但界面须展示来源和使用限制，安装须由用户触发。若未来支持其他用途，应换成适用的授权或权重，再重测检出率、框与关键点格式和完整候选质量。
- 先探测平台硬件、驱动、运行时、模型算子和内存预算，**优先选择实测可用的硬件推理配置**；不支持的算子、设备不可用或显存不足时回落到声明支持的配置。每次分析记录所用完整 pipeline fingerprint、执行后端及设备；推理失败、模型丢失、OOM 可暂停并重试，不得把失败结果提交为空检测。用户可切换已安装的 pipeline，切换后显示重算范围、预计资源与旧建议保留情况。

### 图片输入复用与有界解码

人物分析通过 `oxy-media` 新增的内部 `AnalysisInput`／`prepare_analysis_input` 边界取得源表示，不另写一套 JPEG、RAW、HEIF 路径。此边界接收 `SourceRevision`、模型输入所需的最小有效细节、方向／色彩要求和取消令牌，返回所选表示的来源、有效内容尺寸、方向变换、颜色空间及源版本。复用现有 representation planner、合格的内嵌 JPEG、已验证的缓存 artifact 和同源在途生产结果；不得把 WebView 已解码的 `Image`、资源 URL 或尚未完成的持久化路径当作原生可复用像素。现有媒体缓存的版本、manifest、lease 和 generation 校验仍适用。展示用的 160/512 像素缩略图**不能仅因已经存在就作为检测输入**：若其人脸或人体有效像素不足，升级到足够清晰的内嵌图、较大已缓存产物或受控原图解码；仍不足则标为不可判定／待查，不写“无人物”。

当前 `oxy-media/analysis_input.rs` 只完成原生 JPEG 的第一条路径：调用已有 libjpeg 缩放解码，受后台转换内存 gate 与取消控制，在输入前后核对完整 `SourceRevision`，返回已按 EXIF 方向校正的短生命周期 RGB 帧，并标明是否有 ICC。它尚未选择 RAW／HEIF 的合格内嵌表示或验证缓存产物，也没有替模型做颜色空间归一化；这些格式目前明确返回不可用，而不写空检测。模型 worker 接入前还须把 JPEG 输入与具体检测/编码预处理一起验证。

`oxy-people/face_input.rs` 已定义当前研究基线的两种确定性张量：SCRFD 按比例缩放至 320–1280 方形画布、右／下补零、RGB `(pixel−127.5)/128`；AdaFace 用五点相似变换对齐到 112×112，输出 BGR `(pixel−127.5)/127.5`。样例数值已与现有 InsightFace／OpenCV 研究预处理对照，允许不同插值实现的微小差异；这不证明编码向量可直接共用旧阈值，实际模型输出和候选质量仍需端到端校准。`oxy-people/onnx_face.rs` 共用预处理后的推理、SCRFD 九张量校验／多人解码以及 AdaFace 512 维 L2 特征；Windows 已用本机研究模型跑通 Windows ML CPU／DirectML，macOS 的 Core ML 分支已预接但尚未在 Mac 上构建或实测。检测结果可转换为缓存记录，框与五点按分析图尺寸归一化，五点在编码时按同一朝向的分析图还原；检测缓存 schema 版本 2 重建旧派生表，人工框与审阅记录不受影响。检测阈值由调用方选择，尚未通过未见场次校准；真实作业 worker 与主应用安装包内的运行时部署仍待实现。

按“探测元数据和候选表示 → 选满足模型要求且预计解码成本最低的表示 → 在目标尺度解码 → 必要的候选区域裁剪／特征提取”执行。JPEG 优先合格的内嵌表示与 libjpeg-turbo 缩放 IDCT；RAW 优先合格内嵌 JPEG，只有确有需要才进入系统或 LibRaw 显影；HEIF/HIF 优先合格的已有表示，macOS 沿用 ImageIO 路径，Windows 沿用现有 WIC／FFmpeg tile／libheif 能力和回退顺序。只有解码器实际支持区域读取或缩放时才请求 ROI／目标尺寸，不声称通用格式都能仅解码脸部块。**不要先把整张原图展开成 RGB/RGBA，再为检测缩小回模型输入尺寸**；不得为了几百像素的模型输入长期保存整幅高分辨率 RGB 中间态。源表示低于要求或解码器无法有界处理时，明确走受内存预算保护的慢路径并记录原因，不能靠低质缩略图掩盖漏检。

同一源版本的一次分析中，检测、质量评估、脸体关联和多个人脸／人体特征提取共享一个短生命周期的已定向输入帧；按检测框从该帧生成有界 crop／tensor，处理完即释放。不同 stage 所需的尺寸、色彩、归一化与 landmark 对齐由各自 manifest 声明，在共享输入上分别变换；不能拿显示锐化、ICC 处理或预览降采样后的像素冒充与训练时一致的输入。可共享的仅是经源版本与呈现语义校验的编码表示或有界像素，不把某个模型专用 tensor 当作通用缓存。跨作业只缓存昂贵且可验证的编码产物和最终特征；原始 RGB／RGBA、crop 和设备 tensor 默认不持久化。并发同图请求用 single-flight 合并源准备／解码，取消最后一个使用者后释放；对旧 generation 的迟到产物不发布。内存预算同时计入解码帧、多个 crop、预处理缓冲、设备 tensor 和模型权重，不只按输出图片或单个 tensor 估算。[统一预览流水线](architecture/03-preview-pipeline.md)、[源表示规划](architecture/08-representation-planning.md)。

### Windows 与 macOS 推理后端

Windows 上 Rust、Windows ML、`ort` 与 `tract` 的运行时／模型实测及选型限制见 [2026-09-24 后端调查](research/2026-09-24-rust-windows-ml-onnx.md)。跨平台 `ort` 设计与 macOS 待验证项见 [后端预设计](research/2026-09-24-cross-platform-ort-backends.md)。适配器已放在 `oxy-people`，但还没有接到主应用作业调度或正式安装包；`tract` 可运行研究模型，但不能替代 Windows ML 的 DirectML／NPU EP，且短测 SCRFD CPU 延迟较高。

执行后端通过模型适配器的能力表选择，不把具体推理框架写进人物数据契约。当前 `OnnxProvider` 在 Windows 提供 CPU／DirectML，在 macOS 提供 CPU／Core ML；两平台都从应用提供且 SHA-256 已校验的 ONNX Runtime 动态库加载相同的 ONNX 模型，Core ML 使用显式计算单元选择、静态输入尺寸和可选的编译缓存目录。阶段 worker 根据真实可用性和整条流水线测量选择 provider；加速 session 创建或运行失败时可重新创建 CPU session，不能把异常结果提交为空检测。当前没有 WinML 自动 EP 选择或 Mac 设备探测。DirectML 目前由上游维持支持但新功能转向 WinML；Core ML 的设备使用也取决于具体模型和运行时构建，注册成功不证明所有算子落在硬件上。[Windows 执行后端](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)、[Core ML 执行后端](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html)。

在每个平台按阶段记录实际 provider、算子回退、输入尺寸、batch、模型加载／编译、解码、预处理、主机与设备传输、推理及结果提交的时间与内存。硬件配置若因算子切分而反复 CPU↔GPU 传输、首图编译过慢或抢占前台预览资源，应允许该模型阶段选择 CPU；不要强制每阶段都上 GPU。检测与编码可分别选后端，但同一阶段的输入／输出语义及特征空间 ID 必须一致，数值差异超出校准范围时分开标记。设备 session 复用并限制并发和 batch 大小；Windows 上若选 DirectML，遵守其 session 的串行运行约束。前台 Loupe／缩略图和 UI 响应优先，后台分析可暂停、降并发或切 CPU；这由测得的资源争用决定，不借用媒体展示队列的 worker 容量来跑推理。

交付前分别用 Windows 与 macOS 的正式 Release 包，在真实 JPEG、RAW、HEIF/HIF 混合文件夹上测冷／热解码、每图与整夹吞吐、首图延迟、峰值 CPU／GPU／内存、NAS 读取量，以及分析时 Grid 滚动、Loupe 切图和缩略图就绪的变化。对同一批合格照片比较硬件配置与 CPU 回退的端到端时间和检测结果；验证方向、色彩、多脸 crop、硬件与 CPU 特征相容性。预设可检验的退化门槛并记录机器/系统/设备，达不到时调整后端或资源上限；不能以“启用了 GPU”或模型推理计时替代 Windows/macOS 的实际高效处理证据。

### 持久化：人工事实与派生缓存分开

人物资料沿用 app data 中的 `oxyviewer.sqlite`——与标签、收藏夹和索引是**同一个文件**，不是另建的库——但独立建表和迁移，表声明写在 `oxy-store/src/schema` 并在声明里标注类别。不要依赖可重建的 `indexed_assets` 行作外键。UUID/稳定不透明 ID 只标识人物、文件夹内的待确认人物和审阅实体，**不生成场次 ID**。文件夹范围以现有 `oxy-fs` 规范化的文件夹路径作为持久键；资产路径附带源文件身份、大小、mtime/版本作核验。`(root_path, path)` 仅表示索引归属：同一文件在重叠 root 中不能生成两份人物审阅事实。文件夹路径因应用内移动而变更时显式迁移相关记录；同路径文件夹被替换或离线重挂出现歧义时要求用户核对，不按名称猜测。分析作业可以有独立的 `run_id`，但它只标识一次运行，不代表场次。

| 表（建议名） | 持久内容与约束 |
| --- | --- |
| `person_folders` | `folder_path` 主键、扫描水位、用户所选 pipeline、分析状态；仅保存该文件夹人物功能的状态，目录打开本身不创建整目录分析作业 |
| `people` | 跨场次稳定人物 ID、显示名／别名、确认状态、可选备注、审计时间；姓名不是唯一键，未确认匿名簇不写入 |
| `folder_person_links` | `folder_path` 与文件夹内待确认人物 ID、可选 `person_id`、用户确认状态及来源；临时身份可无历史人物，之后再关联 |
| `person_instance_overrides` | 人工添加／修正的实例定位、脸体关联、实例锚点、适用源版本；源图变化后标待复核而不悄悄复用框 |
| `person_review_decisions` | `(folder_path, asset_path, instance_anchor, subject_id)` 的当前决定、revision、操作者和时间；`subject_id` 指文件夹内待确认人物或已确认 Person，人工属于／不属于／暂缓独立于模型建议，变化留审计记录 |
| `person_identity_events` | 新建、关联、拆分、合并、改名、撤销和参考变更的可追溯事件；合并保留别名映射和冲突复核 |
| `person_references` | 人工确认的实例锚点、所指人物、源版本、用途和质量复核；不能从自动候选静默提升 |
| `person_analysis_runs` / `person_instances_cache` | pipeline fingerprint、输入源版本、实例框、关联／质量证据、状态和错误；可重建 |
| `person_features_cache` / `person_candidate_cache` | 特征空间 ID、模态、维度、类型、规范化向量 BLOB、候选分数与来源；向量及候选均可重建，按 pipeline/源版本隔离 |
| `person_cluster_suggestions` | 分析运行内的匿名簇和成员；临时 ID 只在该运行有效，绝不作为 `people` 主键 |

建议把当前状态和审计事件分别存储，读当前状态不必回放全部历史。用户事务通过 `revision` 做乐观并发控制；重放同一个 `requestId` 幂等，旧版本提交返回冲突及最新状态。只允许明确的人工命令写 `people`、场次身份、审阅决定、参考及人工修正。缓存 schema 带版本和迁移策略：缓存不兼容时可删后重建，人工资料迁移失败时停止写入并保留旧库，不把人物表当索引清空。备份／恢复应包含人物资料、tag 和映射；恢复时模型可重新下载、派生缓存可重新计算。

实例锚点不能仅为“第 2 张脸”或模型框数组下标。保存照片源版本、人工框/关键点及可选检测证据；重算时用同图几何重叠、关键点与关联一致性做**保守**对齐。唯一可信匹配才把旧人工决定映射到新实例；一对多、多对一、框消失或源图变化均进入冲突队列。人工“不属于”继续压制对应主体的普通候选，不能因阈值或 pipeline 更换复活。未匹配的审阅记录保留为待复核，而非删除或套给邻近的人。

### 向量存储与 sqlite-vec 检索

使用 [sqlite-vec](https://github.com/asg017/sqlite-vec) 扩展管理本地向量和距离计算。第一版将 `person_features_cache` 作为**唯一持久的向量缓存**：每条记录包含稳定的 `feature_row_id`、`folder_path`、`asset_path`、实例缓存 ID、源版本、`feature_space_id`、模态、维度、元素类型、L2 归一化标志、pipeline fingerprint 和紧凑 float32 BLOB。写入前拒绝维度错误、NaN／无穷值、零范数及无效源版本；读取时再核验特征空间和维度。脸与人体、ArcFace 与 AdaFace、同模型不同预处理或权重版本都用不同的特征空间 ID；不能因为都是 512 维就混查或复用阈值。`person_candidate_cache` 只存可重建的排序快照与所用查询配置，不复制一份向量。

当前文件夹检索先在普通表按 `folder_path`、`feature_space_id` 和有效源版本限制集合，再用 sqlite-vec 的 `vec_distance_cosine()` 计算距离，转换为该 pipeline 校准的相似度后执行高召回阈值及稳定排序。普通表加 `(folder_path, feature_space_id, asset_path)` 索引。**阈值检索必须覆盖所有合格实例**；不能先取固定 top-K 再应用 0.300 阈值，否则大文件夹里会漏掉本应进入待审队列的候选。`vec0` 虚拟表可作为大集合的可重建加速层，但必须由 `feature_row_id` 回连普通表确认文件夹、源版本、人工排除和审阅状态；是否采用 partition key 取决于实测，不能给每个小文件夹无条件分片。未来模型维度或距离度量变化时，为新特征空间建立独立 `vec0` 表或索引代次，不修改旧表定义后混入新向量。当前 sqlite-vec 文档明确支持普通表距离函数、`vec0` KNN 和 cosine 距离；`vec0` 的固定 K 查询不直接等价于完整阈值结果。[检索方式](https://alexgarcia.xyz/sqlite-vec/features/knn.html)、[分区限制](https://alexgarcia.xyz/sqlite-vec/features/vec0.html)。

自动候选查询还要求向量的实例 ID、源版本与当前检测阶段缓存同时匹配；检测重跑后留下的旧向量不能作为候选。人工实例和参考使用单独的事实查询，不靠检测缓存存在与否决定其有效性。

`oxy-store` 的写连接和两个 WAL 读连接都须在使用向量函数或访问 `vec0` 前注册**同一固定版本**的扩展，再建表或准备语句；初始化失败只禁用人物向量能力并报告可恢复错误，不影响普通浏览、tag 或人工人物资料。当前仓库使用 `rusqlite` 的 bundled SQLite，优先评估 sqlite-vec 官方 Rust crate 静态链接并在连接初始化时注册；不对任意磁盘路径开放 SQLite 动态扩展加载。sqlite-vec 属于应用的数据库能力，可以随应用打包；**模型权重仍只在用户触发后下载**。记录 sqlite-vec 版本、数据库向量 schema 版本及每个特征空间的格式版本，升级时验证读写兼容；不兼容则删除并重建向量缓存和 `vec0`，保留人物、参考与人工审阅事实。sqlite-vec 目前仍标注 pre-v1，实施时需固定具体版本并在 Windows／macOS／Linux 的打包应用中验证初始化与迁移。[官方仓库](https://github.com/asg017/sqlite-vec)、[Rust 集成](https://alexgarcia.xyz/sqlite-vec/rust.html)。

### 分析作业、增量与查询

`startPersonAnalysis(folderPath, pipelineId)` 是显式、可取消的后台作业。开始时从 `oxy-fs` 分页取得该文件夹快照，只在新／变更源上执行需要的阶段；作业以 `(folder_path, asset_path, source_version, pipeline_fingerprint, stage)` 去重。每个阶段先检查源和作业 generation，推理后提交前再检查一次；迟到结果不得覆盖较新文件、较新 pipeline 或人工修正。按小批次短事务写缓存、持久化进度与失败原因；取消保留已完成的可用结果，下次按版本续跑。限制解码／推理并发、内存和磁盘用量，让可见缩略图、Loupe 与元数据任务优先；不在共享队列锁内解码或写 SQLite。

文件新增进入待处理水位，删除或离线只标缺失并从当前候选查询排除，人工事实暂留以待重连；原图内容变化使相应特征和建议失效。应用内改名／移动／复制／删除需从 `oxy-fs` 操作结果触发人物路径迁移：移动转移事实和缓存路径，复制只复制可复用的派生证据并要求新图重新审阅，永久删除的人工历史是否清理需显式用户操作。对应用外移动先列为待重连，不用不可靠的名称相等自动迁移。tag 路径迁移和人物路径迁移应在同一资料库事务中完成或由可恢复的操作日志补偿，避免两者指向不同路径。

候选查询分两层：先在当前文件夹按指定参考及特征空间取分页、稳定排序的实例候选，再投影为去重照片列表供 Grid／Loupe。返回每张照片的候选实例、模态来源、质量／歧义、分数和审阅状态，不把“照片有此人”推断为所有实例都属于此人。已确认“属于”即使低于模型阈值仍出现于已确认视图；已确认“不属于”从该主体的普通待审结果排除；缺脸／漏检／关联歧义有单独待查入口。过滤与现有文件名、评级、颜色、旗标、tag 条件在同一当前目录快照内取交集，按现有排序及分页返回准确的页和数量；不得取前端已加载页再过滤。多条件变化、切文件夹和切 pipeline 时采用 query key／generation 保护，不让旧页覆盖新结果。检索实现是 `oxy-people` 的一组方法，语句在 `oxy-store::repo::person_cache`（特征空间维度、`search_features` 的阈值过滤与分页都在那一个函数里）；以后增加 `vec0` 加速或替换检索索引时，完整阈值语义、候选排序和分页契约不变。

### Person 与 tag 的兼容和可选同步

**Person 是身份及逐实例审阅事实；tag 是整张资产的分类。** 一张多人照片可对应多个已确认 Person tag；匿名簇、待确认身份、自动候选、仅有参考相似度、手工“暂缓”或“不属于”都不能自动产生 tag。用户在确认场次身份／历史人物时可选择“同步已确认属于的照片到 tag”，并可随时关闭、重启或选择已有 tag；默认不把人物自动塞入现有同名 tag。映射使用 `person_id → tag_id` 的稳定 ID，显示名只作建议，允许重名、别名、改名和移动 tag；绑定已有 tag 时预览受影响照片和冲突。新建 tag 可放在用户选择的父级（例如“人物”），不假定这个节点存在或按名称偷偷合并。场次临时身份只有在明确绑定稳定 Person 后才可启用跨场次 tag 同步；若产品要支持仅本场次 tag，则另设有场次范围的显式映射，不能假装它是跨场次人物。

现有 `asset_tags` 只有 `(asset_path, tag_id)`，无法区分手工赋值与人物同步，直接删行会误删用户 tag。实现前增加 `person_tag_links`（人物、tag、启用状态及策略）和 `asset_tag_sources`（路径、tag、来源种类、来源 ID，唯一约束）或等价的来源账本；把旧版 `asset_tags` 保守回填为 `legacy` 来源，避免迁移时猜测赋值起因。**`asset_tags` 继续作为现有筛选、详情和 XMP 同步使用的有效赋值并集**，由单个事务根据来源账本维护；此后 UI 手工编辑产生 `manual` 来源，sidecar 反向导入产生 `sidecar` 来源，Person 同步产生 `person` 来源。旧版 `legacy` 来源按手工赋值保护，用户第一次显式编辑该 tag 时再转换。sidecar 对账只增删 `sidecar` 来源，不能替代用户或 Person 来源。对同一路径同一 tag，多种来源可以共存。撤销审阅、解绑或删除 Person 只撤相应 Person 来源；其他来源仍在时 tag 保留。手工“移除”若 Person 来源仍生效，UI 要显示来源和“停止此人物在此图同步”选项；后者记录按 `(person_id, asset_path)` 的覆盖，避免下一次重算又自动加回。撤销覆盖须显式操作。

确认／撤销某实例、合并／拆分身份、绑定／解绑 tag、删除 tag 的操作在同一 SQLite 事务中更新人物事实、来源账本、`asset_tags` 并为变化路径入 `tag_xmp_sync_queue`。实现 `person_tag_links` 的 tag 外键时保留断链记录（例如 nullable `tag_id` 加 `ON DELETE SET NULL`），避免现有 `custom_tags` 的级联删除抹掉映射历史。一张照片对某 Person 只要有至少一个**当前有效的人工“属于”实例**就贡献一次 tag；最后一个有效实例撤销才移除贡献。一个人在两场次同路径的重复确认也不能因撤销其中一条而移除另一条有效贡献。tag 改名／移动只更新映射所指稳定 ID 和现有 XMP 路径同步；删除已绑定 tag 时先展示影响，删除后映射置为断开待重绑，不能按旧名称自动创建替代 tag，也不能删除 Person。Person 改名默认不改用户 tag 名；提供明确的联动改名操作，并遵守同级唯一名称限制。人物合并若映射到不同 tag，先让用户选择保留哪一个或均保留；不静默复制所有照片到两个标签。

XMP 仍只写最终有效 tag 集合，并沿用当前受管 `dc:subject`／`lr:hierarchicalSubject` 的合并与持久队列。同步失败不撤销已提交的人物决定，错误与重试状态对用户可见。sidecar 反向导入是 tag 的外部来源，不得反向创立或确认 Person；导入时不能删除人物来源贡献。待写队列存在时仍暂停该路径反向导入，防止旧 sidecar 覆盖刚提交的决定。相同文字的外部关键词与受管 tag 可能合并显示，不能用 XMP 字符串反推稳定 `person_id`；跨应用传递的只是关键词，不保证身份语义。

### IPC、错误与验收顺序

按资源划分命令，不暴露通用“运行模型”入口：`listPersonPipelines`／`installPersonPipeline`／`getPersonModelStatus`，`start/cancel/getPersonAnalysis`，`listFolderPeople`／`listPersonCandidates`／`getPersonReviewContext`，`setPersonReviewDecision`／`setPersonInstanceOverride`，`confirmFolderPerson`／`linkHistoricalPerson`／`setPersonReferences`，`setPersonTagLink`／`setPersonTagOverride`。具体命名实现时可调整，但涉及当前范围的命令必须包含规范化的 `folderPath`，写命令还要包含实例／主体 ID、预期 revision 和幂等 request ID；`cancel/getPersonAnalysis` 可用 `run_id` 定位一次作业。分页用 cursor 与查询 generation；长作业通过状态查询及节流事件报告进度。错误至少区分模型未安装／许可不可用、源版本变化、实例对齐冲突、陈旧 revision、推理失败、tag 冲突和 XMP 待重试。`api.ts`、TypeScript 类型及浏览器 demo 与 `oxy-domain` 同步；demo 可用确定性的实例／候选数据验证交互，不伪装已安装真实模型。

已接入的是人工那一半：`apps/desktop/src-tauri/src/commands/people.rs` 提供 `list_folder_people`、
`list_historical_people`、`get_historical_link`、`get/set_person_tag_link`、`get/set_person_tag_override`、
`get_folder_person_reference_asset`、`get_historical_reference_asset`、`link/unlink_historical_person`、
`create_folder_person`、`confirm_folder_person`、`create/list/update_person_instance`、
`list_person_reviews`、`set_person_review`、`reset_folder_person`，全部转发到 `state.people`。
`listPersonCandidates`、`getPersonReviewContext`、`start/cancel/getPersonAnalysis` 和三个模型命令**尚不存在**，
这不是命名差异而是缺口：领域层已经能回答它们，只是没有命令把它们接到界面上。相应地，人物域的
`PeopleError` 与 `oxy_tags::TagError` 在命令层都还原成 `String`，和原来的 `LibraryError` 处理方式一致。

建议分阶段交付：① SQLite 人工事实、实例审阅和多人物查询，模型缺席也能手工操作；② 可信清单下载与单 pipeline 的检测／特征／候选链路；③ 增量作业、重算对齐及历史身份；④ tag 来源账本与选择性同步；⑤ 替换模型和检测流程的迁移演练。各阶段都验证重启与取消、同图多人、不同源版本、旧作业迟到、模型缺失及手工决定不丢失。tag 阶段增加“手工与 Person 同赋值、撤销最后一个实例、同人多场次、tag 改名／删除、sidecar 导入／写失败、应用内移动／复制”事务测试。最终用真实文件夹及下载后的真实模型验证 CPU／可用硬件后端、分页导航、首屏和后台资源占用；模型阈值仍需未见场次校准，不能以测试通过替代识别质量验收。

## 证据与尚未完成的验证

| 问题 | 目前观察 | 可得结论 |
| --- | --- | --- |
| 单图高召回纯脸 | 干净同场次 test，AdaFace 0.300：366/396 个**同人有向配对**返回，144 个异人有向候选，返回精度 71.8% | 可作为人审候选基线；71.8% 不是“100 张图里恰好 72 张需要”，也不是查询找齐率 |
| 缺脸体貌回退 | 同一 test：396/396 个同人有向配对，228 个异人有向候选，返回精度 63.5% | 本批补回缺脸漏检，但增加审阅量；同服装与跨场次风险未验证 |
| 1 张与 3 张高质量参考 | 可比小池的 test 仅 2 个身份、22 个待检同人实例；单参考加缺脸回退 22/22、4 个错候选；正／侧脸兼顾 3 张重校规则 22/22、1 个错候选 | 3 张在此样本未提升召回；错候选差异不足以将三图设默认 |
| 首次匿名聚合 | E0/E1 后期主 test 某些方法有较高匿名簇覆盖；背影整块留出不稳。E2 质量加权未晋级；E3–E6 没有通过后续门槛 | 先做保守簇＋待查＋人工修正，不能把匿名簇覆盖解释为身份识别率 |

上述 test 在多轮研究中已被观察，均为**探索性结果**；有向配对数不能当作不同照片数。体貌回退实验在查询或候选任一方缺脸时都可用人体分数；上文产品设计要求缺脸查询先重选参考，因此 396/396 不是该交互策略的直接预估。现场候选与查询都应遵守相同清晰正／侧面人体和人脸资格，但现有资格来自人工初审，自动质量过滤尚未验证；检测失败的合格照片仍计入召回。落地前需用未见场次验证：自动质量判断、脸／人体关联、多脸手选、跨正侧脸、缺脸待查、同服装异人、换装历史匹配与拒识；同时实测逐查询错候选**照片数**、人工审阅时间、到片增量延迟和端到端资源占用。
