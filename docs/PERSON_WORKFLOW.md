# 人物工作流

当前实现以全 App 人物身份和照片内实例为核心；本文是交互与数据契约。旧的“文件夹人物 → 场次身份 → 历史人物”多层确认入口已由统一人物库取代。历史实验和旧版界面证据保留在文末研究链接。

## 人物、实例与分组

- **人物**是全 App 共用的稳定 ID、姓名、参考实例和可选标签映射。同一个人物可以出现在任意文件夹，改名与参考变更立即影响各文件夹的投影。
- **实例**是一张照片里的一个人，保存 `optional(faceBox) + optional(bodyBox)`，至少有一项。一张照片可以有多个实例；同一实例的人脸和人体共用归属。纯人体实例支持人工审阅。
- **匿名组**是当前文件夹内的候选实例集合。单例也显示为匿名组；组数不是经确认的自然人数量。
- **已知人物组**按全局人物 ID 汇总当前文件夹的实例。候选命中只产生待确认关系，不会自动确认。
- **审阅决定**针对 `(instanceId, personId)`，状态为待确认、已确认、不属于、暂缓。照片级 tag 是已确认实例归属的派生贡献，不是人物身份本身。

文件夹顶部显示“未知身份 N 组 / 已知身份 M 人”。已知数包含有候选或人工归属的人物，不包含只有排除记录的人物。未检测到人脸和证据失效单独报告，不把失败当作无人。

## 人物总览与看图确认

“设置 → 常规 → 功能模块”提供“显示人物模块（实验性）”开关，默认关闭，设置在本机保存；已有的显式开启选择仍保留。关闭后隐藏侧栏人物入口并退出人物视图，照片浏览不再应用人物筛选或显示人物框；再次开启后可从侧栏进入。隐藏不会删除人物、人工标记、归属或审阅记录，也不取消已提交的后台分析任务。

进入“人物”首先打开主窗口的全局人物总览，可按姓名搜索所有已有身份；无需先打开文件夹。人物卡片显示人工确认标记数、来源文件夹数和参考数。进入人物后按来源文件夹组织已确认照片，每页 24 个文件夹，接口最多 60 个。后端先按完整文件夹聚合再分页；卡片显示该文件夹内此人物已确认照片的封面、名称、去重照片数和确认标记数。封面路径随分页聚合返回，进入可见区域后才通过现有缩略图管线加载，不扫描目录；原图离线时保留占位。路径最多显示两行，超出省略，悬停可查看完整路径。同名文件夹以完整路径区分，离线记录仍保留。单击选中，双击或 Enter 打开真实目录并保留在“人物”标签的当前文件夹工作区：复用最近的已打开祖先根，必要时注册新根，左侧文件夹区域自动展开，目录树逐层展开并滚动到对应位置。打开失败保留人物页并提示原因。没有参考的确认记录同样计入；候选、暂缓与排除不计入。

选择“当前文件夹”进入审阅。左侧最上方“看图确认”跟随主窗口照片，逐人显示序号、姓名与状态。点击人物行与大图对应框联动，直接确认、排除或暂缓一个实例；同图的其他人不受影响，默认各用自己的候选身份。显式选择其他人物后，按钮写出将确认的姓名。大图展示当前照片的全部实例，不因分组只留下其中一人的框。切换照片会重置快捷指定并回到侧栏顶部，确认不跳到下一张。

Grid 多选照片时，“看图确认”按人物汇总选中照片中的实例，人物左侧数字同步显示选中实例数，顶部显示照片数和实例总数。每行的确认、不属于和暂缓批量作用于该行全部实例，沿用同一事务与版本校验；当前人物分组和审阅状态过滤继续限制操作范围，不会把同图其他人物一并处理。单选或进入 Loupe 后恢复逐实例确认。

视觉沿用暗色照片工作台，以蓝色表达选择、绿色表达确认；人物页侧栏最低 280px。总览隐藏检查器，较窄桌面窗口优先留出照片空间。字号、留白、渐进展开和短暂的操作反馈建立层级，键盘焦点可见，减少动态效果偏好关闭过渡。

## 左侧模块

| 模块 | 用途 |
| --- | --- |
| 当前文件夹 | 显示统计，执行自动分组或寻找人物；只处理当前目录，不递归 |
| 识别选项、模型与进度 | 调整候选阈值、显式重新提取特征，安装模型，查看原任务范围、进度、失败与取消 |
| 全部人物 / 当前文件夹 | 在全局历史与当前拍摄的审阅之间切换 |
| 看图确认 | 跟随主窗口照片，逐人一键选中、确认、排除或暂缓 |
| 人物资料 · 新建与管理 | 新建和改名、查看和移除跨文件夹参考、绑定已有 tag 或关闭同步；在总览中默认展开 |
| 人物分组 | 选择已知人物或匿名组，驱动同一套 Grid / Loupe 过滤；选择后折叠列表，方便审阅 |
| 实例归属审阅 | 过滤状态与实例列表；批量操作和替换归属收起到次级区域 |
| 标记与修正 | 新增人脸或纯人体实例；为同一实例修正面部、关联或修正人体；控制图上框显示 |

Ctrl / Command 多选，Shift 连选；复选框逐项选择。“整组转为待确认”作用于组内所有实例，“指定为待确认”等按钮只作用于选中的实例。每页最多 30 行实例预览。更改审阅决定不会自动跳到下一张照片：Loupe 保留当前审阅照片，若它已离开筛选集合会明确提示；Grid 和胶片条仍只显示筛选结果，用户选择下一张或切换分组后继续正常导航。

## 两种文件夹操作

**自动分组**：没有兼容特征时先检测与编码；用现有特征构造保守匿名组，再以全局明确参考查询已知人物，输出匿名组与已知人物待确认组。

**寻找人物**：勾选已有的全局人物，仅为这些人物查询待确认候选；不执行匿名两两聚类。每个选中人物必须有当前模型可用的人脸参考，否则明确报错。旧的人工确认、排除和手工实例仍保留，任务不会清空用户资料。

两者使用同一后台 operation 和取消协议。已有兼容特征不需要重新加载模型；显式勾选“重新提取”才重跑特征，缺失／不兼容特征也会进入提取。分析完成后继续分组或检索，结果发布后操作才完成。切换目录不会修改正在运行任务的范围。

## 统一确认流程

匿名组可以整组转为选定人物的待确认组，也可以进入图片逐实例指定不同人物。选中某一人脸不会把同一照片中的其他人一起归属。

批处理在一个事务内核对工作区 revision、实例 revision 与源版本，全部有效才提交；重复 requestId 返回相同结果。转为待确认不会覆盖已有人工决定，包括“不属于”。指定新的已确认人物需要明确勾选替换已有归属；替换保留旧人物的排除记录。否定其他候选不会删除已确认的正确人物。

明确确认后，可把该实例设为全局参考。参考由用户显式选择，候选不能自动成为参考；撤销归属或修改框会撤下参考。修框保留旧值到审计事件，非否定决定回到待确认，否定决定继续保留。源变化、陈旧版本或歧义对齐不得绕过人工复核。

Grid / Loupe 共用后端按整目录快照进行的实例过滤，与原有文件名、类型、评级、旗标和 tag 条件取交集，再排序、去重和分页。普通打开目录、读取侧栏不会触发模型、目录递归扫描或重新聚类。

## 算法与研究结论

当前推理为 Windows x64 的 SCRFD + AdaFace WebFace12M，ORT DirectML device 0；统一媒体输入支持 JPEG、RAW、HEIF/HIF、PNG、WebP、TIFF。使用已核对的 RGB 输入及独立特征空间，不能把 WebFace4M 的旧阈值或研究指标当成 WebFace12M 的精度保证。

匿名核心使用 complete-link cosine 0.50：所有跨组成员必须达到阈值，且同一照片的两个人脸不能合入同组。已知人物检索取与明确参考的最大 cosine，默认候选阈值 0.40，可由用户调整；自动分组中前两个人物分数相差不足 0.05 时保留未知，定向寻找允许作为多个已选人物的待确认候选。以上均为探索性的人工审阅阈值。

遵循 model-research 的保守结论：E2–E6 未通过晋级门槛；人体／衣着相似度不能直接确认身份或扩张参考库。当前支持人体标注与人工关系，但未接入自动人体检测／特征匹配。手画人脸只有与缓存检测唯一对应时才有可复用的人脸向量；没有可用参考向量时明确提示，不用其他人的脸替代。

参考特征要求相同完整源版本和当前编码空间，框按数值容差 1e-9 唯一匹配，容纳 JSON 浮点往返误差。重新检测结果通过保守一对一几何对齐携带人工实例；歧义结果要求复核。

检测、对齐与人工框使用同一归一化边界校验：右／下边缘允许 `8 × f64::EPSILON`
的浮点舍入误差，避免贴边框在 JSON 持久化后导致整个文件夹无法读取。保留原始坐标与
实例 ID；非有限数、负起点、非正尺寸和超出该容差的越界仍拒绝。已有结果无需重新识别。

当前单目录上限 5000 个人脸，匿名聚类稠密矩阵加候选边最坏约 200 MB，不含应用其他内存。定向寻找跳过两两矩阵。发布前重新核对源版本、当前运行、参考和证据，取消或陈旧任务不能覆盖更新的结果。

## 存储、迁移与标签

`oxy-domain` 定义序列化契约，`oxy-people` 拥有策略与事务，`oxy-store` 拥有 SQLite/schema/repository，Tauri 只组合后台任务。前端命令统一在 `api.ts`。

`global_people`、`global_person_migrations`、`global_person_reviews`、`global_person_targets`、`global_person_references`、`global_person_events`、`global_person_tags` 以及人工实例属于 `user`；检测、向量、运行账本、`global_person_suggestions` 与旧匿名快照属于 `cache`。清缓存保留所有姓名、人工框、归属、排除、参考和事件。

旧资料按明确的历史关联合并到全局 ID；仅同名不会自动合并。原文件夹身份、旧审阅与事件不删除，迁移映射阻止重复导入。同一全局人物的旧决定矛盾时保留明确排除，其他冲突转为暂缓；不以迁移顺序选择确认。没有历史关联的旧人物生成独立全局 ID。旧入口仍兼容，但主界面统一使用全局流程。

人物绑定 tag 后，同一照片至少有一个有效已确认实例才贡献一次 `person` 来源。关闭映射、修框或撤销最后一个确认只撤下人物贡献，手工／sidecar 来源保持独立；有效标签变化沿用持久 XMP 队列。保留旧版逐照片的同步排除。同目录改名沿用既有实例迁移；跨目录文件移动仍需复核，不等同于人物跨目录复用。身份合并拆分、自动人体检索、未见场次阈值校准及 macOS 推理实机验证尚未完成。
