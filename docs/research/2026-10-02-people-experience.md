# 人物总览与看图确认验收

2026-10-02，Windows Release / WebView2。当前交互契约见
[人物工作流](../PERSON_WORKFLOW.md)。本次是在已有全局人物身份、分组与人工审阅实现上完善入口和视觉组织，没有重做识别算法。

## 交互证据

使用独立数据库、缓存和 WebView2 profile，原图只复制到忽略的验收目录。
主验证集为四张真实 33MP JPEG，包含两位人物和三个文件夹。没有更改真实人物库。

- 不先选择某个人物文件夹即可浏览所有全局身份；卡片的确认数与文件夹数来自正式分页接口。
- 同一人物在两个文件夹的确认照片同时出现，点击进入大图可以查看框与来源。
- 当前文件夹多人照片中，两个人分别显示自己的候选姓名。选择第二个人时图上选择态对应同一个实例。
- 只确认一个人后，同照片另一人仍待确认。显式更换身份的替换规则继续由后端校验。
- 在待确认过滤中确认最后一张后，过滤结果为零，当前照片仍留在 Loupe，显示已离开筛选集合的提示。
- 在 1080×680 的最小桌面视口，侧栏占 280px，主照片区 800px，没有横向溢出；较窄窗口隐藏检查器。
- 快捷确认区 axe 扫描：0 violations，17 passes；5 个文本节点因背景伪元素而无法自动判定对比度，不能把它声称为完整 WCAG 认证。

## 视觉自评与迭代

| 维度 | 取舍与本轮修正 |
| --- | --- |
| 排版 | 人物姓名与照片为主体，总览标题、姓名、记录说明三级字号；侧栏按钮不依赖图标猜意图 |
| 留白 | 总览采用疏朗的照片集布局；审阅侧栏压缩为当前照片的动作，其他设置逐级展开 |
| 视觉层级 | 全部人物与当前文件夹分开；看图确认在前，批量替换与模型设置退到次级 |
| 色彩 | 沿用暗色看图环境，蓝色选择、绿色确认、琥珀色待复核；去掉人物框与侧栏颜色不一致的问题 |
| 动效 | 只使用短按钮与边框反馈；不对照片施加装饰性进场，遵循 reduced-motion |
| 微交互 | 逐人一键确认，保留当前照片；切图清除快捷身份覆盖，操作成功说明确切结果；空、搜索无结果与失败均有说明 |
| 响应式 | 按桌面实际最小窗口验证，侧栏最低 280px；总览自动分列，窄窗口让出检查器空间 |
| 原创性 | 以人物确认记录组成跨目录照片集，封面围绕对应人物框裁切；避免合照中不同人物使用无法辨别的相同全景封面 |

第一轮实机修正了总览复用照片工作区行高导致的裁切；第二轮修复跨目录预览准入，
以及多人快捷确认错误继承当前分组姓名；之后修正侧栏回顶、框序号、全局底栏和总览返回。
这是对实际任务的设计评审，不等同于 Awwwards、Webby 或 FWA 的评奖结果。

## 工程验证与边界

前端类型检查、389 项前端测试、759 项 Rust 工作区测试与 Release 构建通过。
新增测试覆盖跨目录确认历史分页、离线记录、多人独立决定、历史 HEIF preview 请求与取消、

没有为通过检查而修改这些范围外代码。

确认资料不会丢失。此限制未解决，不把 33MP 场景成功视为任意分辨率的性能保证。
