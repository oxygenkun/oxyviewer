# 人物阶段一：人工工作流验证（2026-09-23）

## 范围

阶段一覆盖模型缺席时的人工工作流：当前文件夹主体、Loupe 人脸／人体框、逐实例审阅、共享 Grid／Loupe 的人物过滤、场次称呼及单张参考管理、SQLite 持久化与冲突保护。自动检测、检索、分析作业、历史身份、三参考、拆并簇和 tag 同步不在本阶段。

## 实现边界

- 人物筛选先与当前目录完整快照相交，再通过已有排序分页返回。多人图去重；姓名搜索在人物过滤下限于当前文件夹，避免借用全资料库 FTS 范围。类型、评级、旗标、颜色和 tag 继续取交集。
- 人工修框保留旧实例 JSON 和审阅事件；所有相关审阅 revision 推进，非否定决定变为待确认，明确否定仍保留。参考失效与场次身份确认独立。
- 所有人工写命令使用 requestId；更新使用 expectedRevision；Tauri 的文件与 SQLite 操作在 spawn_blocking 中执行。没有模型下载或推理路径。
- 已保存人工资料在数据库重新打开后恢复。浏览器 demo 使用内存记录，刷新页面不模拟磁盘持久化。
- 当前源版本是文件大小加毫秒修改时间，不能识别刻意保持两者相同的文件替换。完整文件身份／高精度源版本、文件移动迁移、重算对齐与作业 generation 留给后续实现。

## 浏览器操作

通过独立 agent-browser 会话在本地 demo 实际操作：

1. 打开文件夹，切人物 Tab，手工创建匿名主体。
2. 打开 Loupe，在画布创建两个独立人脸框；第二个框使用真实鼠标拖动。
3. 切换“待确认”过滤，照片只出现一次；确认第一个实例后照片保持不变，第二个仍待确认，左栏待审数从 2 变为 1。
4. 打开管理覆盖页，填写称呼、选择已确认实例作为参考并明确核对清晰度；保存后回到相同照片，第二个实例仍待确认。
5. 截图检查选中框为红色，未选框为蓝色，右侧原图片详情仍可见。demo 主图是占位显示，此项只证明 UI 状态与操作，不能证明原生图片坐标或识别质量。

## Windows release / WebView2

使用 `cargo build -p oxyviewer --release --features tauri/custom-protocol -j 1` 的嵌入前端 release 程序，单独的 OXY_PERF_DATA_DIR / OXY_PERF_CACHE_DIR，以及 3 张真实 JPEG 副本（首张 6336×9504，约 3.4 MB）。原照片与用户资料库未修改。

- 实际完成新建匿名人物、鼠标拖动添加人脸框、在同一实例上修框、确认“属于”、在覆盖页保存场次身份和单张参考；右侧图片详情仍可见。
- “已确认属于”过滤将 3 张照片变成正确的 1 张，Loupe 与胶片条结果一致。截图确认框覆盖实际人脸，选中框为红色。
- 关闭进程后的 SQLite 检查：主体、实例、当前审阅、修框事件和参考各 1 条；身份已确认。随后实际重开 release 进程，人物名称、已确认身份、单张参考及修正后的实例恢复；切到“已确认属于”后仍为 1 张照片、1 个框、决定“属于”。数据库单元测试同时覆盖重新打开后读取一致性。
- 初次运行场景开始到首屏绘制 **207.2 ms**；第一次 listAssets IPC **6.3 ms**；从选择到完整 JPEG 显示 **456.5 ms**。在这一小文件夹上低于 300 ms / 800 ms 参考数值；不等价于 10 万文件首屏预算验收，也不证明未测的热缓存 150 ms、长滚动或跨平台指标。未清 OS 文件缓存。
- 原生测试期间胶片条仍显示占位图而 Loupe 已显示真实照片；本次确认的是人物框、原生写入和过滤，不把它作为缩略图全链路验收通过的证据。
