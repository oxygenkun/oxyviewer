## 实际操作结果

1. 在人物页打开“管理模型”，逐项点击下载 SCRFD、AdaFace WebFace12M、Windows ML。
   三项均从网络下载并通过长度／SHA-256 检查，随后识别按钮启用。
   ONNX 实际文件大小分别为 16,923,827 和 260,704,652 字节。
2. 下载中点击取消，任务转为已取消；安装目录未留下正式文件或临时半成品。
3. 点击“识别选中文件夹”，三张原始 60 MP JPEG 全部完成：6/6 阶段、0 失败，
   SQLite 中产生 3 条检测及 3 条 512 维 float32 特征（每条 2048 字节）。
   特征空间为 `adaface-webface12m-f2eb07d0-v1`。
4. Loupe 显示位置正确的虚线人脸框。点击“采用检测人脸 1”后产生匿名人物和待确认
   实例，`identity_confirmed=0`。明确点击“不属于”后重新分析，决定仍为
   `doesNotBelong`、revision 2，未变回 pending。
5. 关闭并重启应用：模型仍就绪，人物及否定决定保留；切到第二张照片直接出现已保存
   的检测框，不需重新运行模型。重启不自动继续历史运行。

截图：`detected.png`、`review-preserved.png`、`reopened-detection.png`。

## 性能观察与修复

三图成功运行账本分别记录 16 秒和 15 秒。账本在模型加载后开始，且时间字段为秒级，
因此这不是精确的按钮到显示端到端延迟。第一次成功运行主进程峰值工作集为
655,536,128 字节（约 625 MiB），不包含 WebView 子进程。仅为三图冒烟观察，不能
推广到数千张混合格式、NAS 或所有设备，也没有完成正式安装包／跨平台性能矩阵。

实机测试发现并修复：

- 下载器未采用 Windows 系统代理及系统信任库，出现网络断开／证书链错误。
  现启用系统代理，使用平台证书校验，模型及运行时摘要仍独立核验。
- 默认 HTTP Trace 输出二进制 body 的十六进制内容，大幅放大日志并拖慢下载。
  应用对 `ureq`、`ureq_proto` 保留 Warn 以上日志。
- 原 256 MiB 缩略图转换预算拒绝 60 MP JPEG 的保守渐进式系数内存估算
  （本次约 404 MB），导致 6 个任务明确失败、没有写空检测。人物输入改为独立
  单槽 512 MiB 临时预算；缩略图预算仍为 256 MiB。模型 session 内存另计，超限
  图仍明确失败。检测与编码共享一张有界定向 RGB 帧。

原失败运行保留在测试账本中，随后两个新运行成功；不能把旧失败记录当作当前失败。
