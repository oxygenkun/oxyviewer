# 顶部搜索栏与标签筛选设计

状态：基础标签筛选已实现（2026-09-16）；完整第一阶段验收仍有待补齐项。

本次按“完成最基本的标签筛选”落地：`#` 建议、稳定 ID token、子树 AND/OR 批量匹配、
与文件名和现有过滤器组合、会话最近使用、输入法与键盘交互、窄窗口折叠、清除、错误/空态。
查询仍使用原有分页接口；标签查询只针对当前目录快照。纯文件名查询保留既有行为，
完整资料库索引可用时仍可能走根目录 FTS，尚未统一为本文规划的当前目录包含匹配。

待后续完整验收：按光标位置编辑中间的 `#` 片段、长路径中间截断、完整查询文字摘要、
真实大目录快速切换标签的端到端并发/媒体队列测量，以及各平台输入法和读屏人工验证。
目前补全识别输入末尾、位于开头或空白后的 `#` 片段；输入防抖未启用，保留即时提交。


本文固化 OxyViewer 顶部搜索栏的下一阶段设计。目标是在不增加浏览页视觉负担的前提下，
让用户用同一个入口按文件名搜索并按自定义标签缩小当前浏览结果。本文包含已落地基础功能和后续验收目标；性能与数据边界仍以
[浏览与媒体性能约束](../PERFORMANCE_INVARIANTS.md)和
[状态、数据与安全边界](../architecture/05-data-and-state.md)为准。

## 1. 目标与范围

第一阶段解决以下任务：

- 直接输入文件名片段，继续筛选当前目录中的图片；
- 输入 `#` 搜索已有自定义标签，并把选中项保留为可见、可删除的标签 token；
- 同时使用文件名、多个自定义标签和现有类型/评级/颜色/旗标过滤；
- 通过鼠标或键盘完成同一套操作；
- 在窄窗口中仍能看出标签筛选处于生效状态。

第一阶段不包含跨资料库搜索、路径或文件夹名搜索、保存搜索、复杂查询语言、在搜索建议中
新建/改名标签，以及内嵌只读关键词筛选。标签管理仍由现有标签编辑器负责。这样搜索入口只做
“查找和筛选”，不会因输入文字意外改变用户数据。

## 2. 信息结构

顶部工具栏保留一个主搜索控件；类型、评级、颜色、旗标和排序继续留在第二行过滤栏，避免把
所有过滤器塞进同一个不可扫描的菜单。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ☰  WORKSPACE · 2,418 张   ┌──────────────────────────────────┐  视图 │
│                           │ 🔍 [人物 › 家人 ×] 海边…   ⌘K │       │
│                           └──────────────────────────────────┘       │
├──────────────────────────────────────────────────────────────────────┤
│ 全部 RAW JPEG HEIF       ★★★★★  ● ● ● ● ●   旗标      排序          │
└──────────────────────────────────────────────────────────────────────┘
```

搜索框取得焦点时在其下方打开建议面板，不改变工具栏高度，也不推动图片网格。面板最多包含三段：

1. **已选标签**：仅在有标签 token 时出现，并提供“全部满足 / 任一满足”切换；
2. **最近使用**：输入为空时显示，最多 6 个；
3. **匹配标签**：输入 `#` 后按名称和完整层级路径匹配已有标签。

没有便宜、已缓存的准确数量时，建议项不显示图片计数。不得为了装饰建议列表而扫描目录、读取
sidecar、请求 metadata projection 或逐图片查询标签。

## 3. 输入与标签 token

### 3.1 普通文字

不在标签补全状态时，输入内容只做大小写不敏感的文件名包含匹配，保持现有搜索语义。占位文案为
“搜索文件名，输入 # 筛选标签”。文件名搜索与标签过滤同时存在时，两组条件使用 AND。

### 3.2 标签补全

- 在空输入或空白之后输入 `#`，进入标签补全；`#` 后的文字只过滤建议，不参与文件名搜索。
- `↑` / `↓` 移动高亮，`Enter` 选中，`Esc` 关闭建议，鼠标点击与键盘行为一致。
- 选中建议后，将标签变成 token，并从文本输入中删除对应的 `#...` 片段。
- 已选标签不再出现在可选建议中；没有匹配项时显示“没有匹配的标签”，不提供创建动作。
- 必须正确处理中文输入法 composition；拼音组合期间不得提交建议或触发不完整查询。

token 使用 `父级 › 子级` 的显示路径，而不是只显示叶节点名称，因为不同分支可以存在同名标签。
路径过长时在中间截断，悬停或键盘聚焦时可读取完整路径。每个 token 都有独立的移除按钮：

- 输入为空时按 `Backspace`，第一次选中最后一个 token，第二次删除；
- 移除按钮具有可访问名称，例如“移除标签：人物 › 家人”；
- 搜索框尾部的清除按钮只清除文件名文字和自定义标签 token，不清除第二行过滤栏条件。

## 4. 查询语义

查询采用分组规则，界面不要求用户理解布尔表达式：

| 条件组 | 组内规则 | 与其他组 |
| --- | --- | --- |
| 文件名 | 单个包含条件 | AND |
| 自定义标签 | 默认 AND，可切换为 OR | AND |
| 文件类型 | 单选 | AND |
| 最低评级 | 大于等于所选星级 | AND |
| 颜色标签 | OR | AND |
| 旗标 | OR | AND |

选择一个层级标签时，默认匹配“该标签或任一后代标签”的明确分配。例如选择 `人物` 会匹配明确
分配了 `人物`、`人物 › 家人` 或 `人物 › 客户` 的图片；选择 `人物 › 家人` 只扩展它自己的
子树。该规则让上层标签成为可用的分类入口，同时不改变数据库中“分配子标签不会隐式分配祖先”
的事实。

多个标签默认为“全部满足”。例如 `旅行` 与 `五星候选` 两个 token 只返回同时命中两个标签
子树的图片；用户可在建议面板的已选标签区域切换为“任一满足”。切换只影响自定义标签组，
不改变颜色或旗标的既有规则。

结果摘要使用完整查询返回的总数，例如“旅行 + 五星候选 · 36 张”。结果仍在原有网格或
放大视图中呈现，不创建独立搜索页。

## 5. 状态和数据边界

搜索控件维护两类不同状态：

- **已提交查询状态**：文件名文字、标签 ID 列表和标签组合方式，属于 workspace 的同步 UI 意图；
- **临时控件状态**：当前 `#` 片段、建议开关、高亮项和 token 的待删除状态，仅属于搜索组件。

查询必须使用稳定的标签 ID，显示名称和路径只用于呈现。标签被改名或移动后，活跃 token 保持同一
ID 并刷新显示路径；标签被删除后，安全移除对应 token 并重新执行查询。第一阶段不要求跨重启保存
搜索文字、标签 token 或最近使用列表；最近使用可以作为本机 UI 偏好在后续实现，若未持久化则仅保留
当前进程会话。

若实现需要扩展公开查询契约，应在 `oxy-domain` 的 `AssetQuery` 中加入 camelCase 序列化字段，
同步更新 `apps/desktop/src/types.ts`、`apps/desktop/src/lib/api.ts` 和浏览器 demo。标签集合运算应位于
`oxy-library` 或合适的可复用 Rust crate，`src-tauri` 只做薄命令适配。不得用前端逐图片 IPC 查询
拼装结果。

## 6. 响应式与视觉规则

- 常规窗口中搜索框可在现有工具栏中心区域增长，但不能挤掉视图和 Inspector 控件。
- token 使用中性深色底和低对比描边；颜色只表达交互状态，不借用评级/颜色标签的语义色。
- 搜索框中优先完整显示当前输入和第一个 token；空间不足时其余项折叠为 `+N`。
- `+N` 是按钮，激活后在建议面板的“已选标签”区域显示全部 token，不允许把生效条件彻底隐藏。
- 窄窗口仍保留搜索图标、输入区域和 `+N`；快捷键提示可先隐藏。
- 焦点、悬停和选中不能只依赖颜色区分。所有可点击目标至少为 24 × 24 CSS px。
- 动画只用于面板的短淡入/位移，并遵循 `prefers-reduced-motion`；过滤结果不做逐卡片入场动画。

## 7. 键盘与无障碍

- `⌘K`（macOS）或 `Ctrl+K`（Windows/Linux）从应用任意非文本输入区域聚焦搜索框；若已聚焦，
  不清空已有条件。
- 搜索输入使用可编辑 combobox 语义，建议列表使用 listbox/option，并通过
  `aria-expanded`、`aria-controls` 和 `aria-activedescendant` 关联。
- 结果总数变化通过一个 `aria-live="polite"` 区域合并播报，连续输入时不逐字符打断读屏。
- `Tab` 可以离开搜索控件，不制造焦点陷阱；建议关闭后焦点仍留在输入框。
- `Esc` 只关闭建议或取消当前 token 待删除状态，不擅自清除已提交查询。

## 8. 性能与并发约束

- 搜索和标签变化不得重新打开目录、递归扫描文件系统或启动图片解码。
- 已加载页上的纯文件名过滤应继续满足一帧内响应；需要 Rust/SQLite 的标签查询可异步完成，界面
  保留上一份结果并明确显示正在更新。
- 输入查询可使用约 120–180 ms 的防抖；点击 token、移除 token 和切换 AND/OR 应立即提交。
- 每次查询携带稳定的查询身份或 generation；较早请求晚到时不得覆盖较新的输入结果。
- 标签筛选必须批量完成并保持分页，不能先读取每张图片的标签再在前端过滤，也不能为了准确总数
  强制完成 metadata enrichment。
- 激活或取消过滤不驱逐当前目录已经保留的缩略图，不改变可见/附近/后台任务的优先级和取消语义。
- 打开文件夹的廉价、非递归、分页路径保持不变；标签筛选是打开后的显式用户操作。

## 9. 空态、错误与反馈

- 没有结果时显示“没有符合当前搜索和筛选条件的图片”，并提供“清除搜索和标签”动作；该动作
  不清除第二行过滤器。
- 标签列表读取失败时，文件名搜索仍可使用；建议面板说明“标签暂时不可用”，并提供重试。
- 标签查询失败时保留上一次成功结果，显示非模态错误，不把失败误呈现为零结果。
- 索引或标签数据仍在更新时可以逐步发布结果，但必须拒绝旧 generation，且不能让结果总数倒退后
  又被旧请求恢复。

## 10. 实施顺序与验收

建议按以下边界实现，每一步都可独立验证：

1. 将文件名输入拆成可测试的 combobox/token 控件，保持现有查询行为；
2. 加入标签建议、稳定 ID token、层级路径显示和键盘交互；
3. 扩展跨层查询契约，实现标签子树及 AND/OR 批量筛选；
4. 补齐响应式、错误/空态、读屏播报和真实 WebView 验收。

完成标准：

- 文件名、单标签、多标签 AND、多标签 OR 与所有现有过滤器组合结果正确；
- 父标签包含后代、同名叶节点、标签改名/移动/删除均保持明确行为；
- 中文输入法、键盘全流程、读屏角色和焦点恢复通过测试；
- 窄窗口不会隐藏全部活跃条件，也不会使工具栏关键操作不可达；
- 快速连续输入和切换标签时无旧结果覆盖；
- 真实大目录中没有递归扫描、逐图片标签 IPC、额外 metadata/decode 入队或缩略图驱逐；
- 前端 `check`、测试和构建，以及 Rust 格式化、Clippy 和相关 workspace 测试全部通过。
